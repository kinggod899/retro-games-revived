# 工程档案脱敏说明

> 适用范围：「喵星忍者」与「小小部队」两款游戏复活工作产生的文本工程档案。不含 VoxCut（开发录音机）任何内容。
> 产物根：E 盘工作区下 _repo_staging\engineering\。全部文件以 UTF-8 无 BOM 写出。

## 一、脱敏规则（逐条）

1. Windows 绝对路径：盘符 + 一级目录（工作区根、工具链根、素材目录根、系统根等）统一替换为 `<WORKSPACE>`，保留其后的相对尾段（例如 `<WORKSPACE>\out\交付说明.md`）。单反斜杠与 Markdown 中转义用的双反斜杠两种写法均覆盖。
2. 用户目录：盘符 + Users + 用户名三段整体替换为 `<WORKSPACE>`，保留用户名之后的相对尾段，避免真实用户名残留。
3. QQ 号：两枚 10 位数字标识替换为 `<QQ_ID>`；同域邮箱整体替换为 `<EMAIL>`（邮箱规则先于裸号执行，防止留下半截占位符）。
4. 设备标识：adb serial（模拟器序号形式）、调试端点（IP 加端口）替换为 `<DEVICE_ID>`；Facebook appId 等第三方标识值按精确语境替换为 `<REDACTED>`。经逐处语境核对后，不做宽泛长数字匹配。
5. 密钥实物：名为 debug keystore 的密钥文件及其别名文件不复制；文字引用中的密钥文件名替换为 `<KEYSTORE_FILE>`。
6. 口令与别名：keystore 口令、key 口令、别名、token、API key 的具体值替换为 `<REDACTED>`，字段名与说明性文字原样保留。JSON 中仅替换值、保留键名。
7. 长十六进制与长数字串：经逐长度、逐语境核对，32/40/64 位为 MD5/SHA-1/SHA-256 哈希，12/13/16 位多为 ELF 节址与内存指针，20 位以上纯数字为 VP 视口矩阵浮点数据，15 位以上纯数字片段出现在经纬度小数与 ELF BuildId 十六进制串中——均属技术事实，按「不得误伤」条款原样保留；仅对带明确设备标识/凭据字段名的 JSON 值做替换。

8. MSYS2/POSIX 路径：挂载点 `/[A-Za-z]/<本地目录>` 与「盘符 + 正斜杠 + 本地目录」两种写法同样视为本机绝对路径；挂载点连同盘符后一级目录替换为 `<WORKSPACE>` 并保留其后的相对尾段（正斜杠沿用原形态），仅残留裸盘符的片段替换为 `<DRIVE>/`（新增占位符，专指 MSYS2 转换后残留的盘符前缀）。本轮为定点补脱敏，仅修正 2 份交付文档中的 3 行，不重生成、不改动其余文件。

### 明确保留的技术事实（未替换）

SHA-256 / SHA-1 / MD5 哈希值、文件大小数字、版本号 1.0.6 / 1.08 / b37、包名 com.chillingo.tinytroopersfree.android.aja 与 com.cafgame.nyankoninja、CP/狗牌数值 999999 / 9999、targetSdk 与 api 数字、VP 视口矩阵浮点数据、ELF BuildId 十六进制串、经纬度小数、外链会话 ID、内存地址与像素数据十六进制串。
