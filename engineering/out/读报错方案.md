# 喵星忍者 真机闪退 — 读报错方案

已交付的 APK (`NyankoNinja_1.08_Compat_api36_IAPunlocked_Noads.apk`, build b39) **内置了崩溃自捕获**。
真机上如果闪退, 它会自动把 Java 异常栈写到:

```
/sdcard/Android/data/com.cafgame.nyankoninja/files/nyan_crash.log
```

下面给出三种读报错的方式, 从易到难。

---

## 方案 A: 一键脚本 (最推荐, 10 秒出结果)

双击 `<WORKSPACE>\out\真机抓崩溃日志.bat`

它会自动:
1. 检查设备是否连上 (没连会教你开 USB 调试)
2. 打印设备型号 / Android 版本 / SDK / ABI
3. 清空旧日志, 强制停止游戏, 重新启动
4. 等 20 秒 (这期间在手机上点开游戏等它闪退)
5. 抓 5 类日志: 完整 logcat / 进程 PID / 包信息 / 解压后的 .so 列表 / tombstone (native 崩溃)
6. 生成 `00_关键报错.txt` 摘要

**产物位置**: `桌面\nyan_crash_<时间>\`

**优先看 `00_关键报错.txt`**, 它已经过滤出 5 类关键信息:
- FATAL / AndroidRuntime (Java 崩溃)
- linker / dlopen 错误 (native 库加载失败) ← **最可能是这个**
- 进程死亡 (has died / exited cleanly / ANR)
- UnsatisfiedLink (JNI 方法找不到)
- 本包相关 ERROR

把整个文件夹发我即可。

---

## 方案 B: 不需要 USB 调试 (用 APK 自己写的日志)

如果不想开 USB 调试, 或电脑上没有 adb:

1. 手机上安装 APK, 点开游戏等它闪退
2. 用手机文件管理器打开:
   ```
   /sdcard/Android/data/com.cafgame.nyankoninja/files/nyan_crash.log
   ```
   (`Android/data` 在有些文件管理器里默认隐藏, 需要在设置里允许显示)
3. 或者用 `MT管理器` / `ES文件浏览器` / `Solid Explorer` 直接导航过去
4. 把 `nyan_crash.log` 内容发我

**局限**: 只能抓 Java 层异常 (`RuntimeException` / `VerifyError` / `SecurityException` 等),
抓不到 native 层 SIGSEGV / SIGABRT。native 崩溃需要方案 A 的 tombstone。

---

## 方案 C: 手动 adb (需要 platform-tools)

```bat
adb devices -l
adb logcat -c
adb shell am start -n com.cafgame.nyankoninja/com.wiyun.engine.skeleton.Skeleton
REM 等闪退
adb logcat -d -v threadtime > crash.txt
adb shell pidof com.cafgame.nyankoninja
```

关注这几类行:
```
E AndroidRuntime: FATAL EXCEPTION
E linker  : library "xxx.so" needed or dlopened by "yyy.so" is not accessible
E linker  : CANNOT LINK EXECUTABLE "...": cannot locate symbol "..."
E art     : Verification error
E AndroidRuntime: java.lang.UnsatisfiedLinkError: No implementation found for
W ActivityManager: Force finishing activity
```

native 崩溃 (tombstone):
```bat
adb shell su -c "ls -t /data/tombstones/ | head -1"
adb exec-out cat /data/tombstones/tombstone_00 > tombstone.txt
```

## 已针对三个根因做的修复 (如果日志确认是这些, 应该不会再崩)

| 根因 | 现象 (日志关键字) | 修复 |
|---|---|---|
| A. AAL dlopen 失败 → exit(1) | `Cannot open android adapter layer` + `exited cleanly (1)` | 自研 AAL stub 补齐 24 个符号 |
| B. .so 压缩+未对齐 → dlopen 失败 | `dlopen failed: library "..." not found` / `Couldn't load ... from loader` | `extractNativeLibs="true"` + `.so` STORED + zipalign `-p 4096` |
| C. libstdc++.so 系统已移除 | `library "libstdc++.so" ... not found` / `CANNOT LINK` | 打包 libstdc++.so 进 APK |

如果日志显示的是**其他**错误, 请把 `00_关键报错.txt` 发我, 我按实际报错继续修。

## 可能的其他闪退原因 (提前列出, 便于对照)

1. **Android 14+ (API 34+) 停止支持 32 位应用**
   - 现象: 直接无法安装, 或安装后启动闪退
   - 日志: `INSTALL_FAILED_NO_MATCHING_ABIS` 或 `Failed to load native library`
   - 这是本游戏的 armeabi (ARMv5) ABI 决定的, 无法从 APK 侧修复
   - 需确认真机系统版本

2. **targetSdk 36 在新系统上的行为变更**
   - 如果日志显示 `SecurityException` / `Permission Denial`, 可能是权限收紧
   - 可以尝试降到 targetSdk 30 或 33 提高兼容性

3. **私有系统库命名空间隔离 (Android 7+)**
   - 现象: `library "libcutils.so" ... is not accessible for the namespace`
   - 本 APK 已自带 libcutils.so/libutils.so/libbase.so/libandroidicu.so/libsqlite.so/libc++.so, 应该不会触发

4. **libandroidicu.so 与系统 icu ABI 不匹配**
   - 现象: `cannot locate symbol "u_xxx" referenced by "libandroidicu.so"`
   - 已把 MuMu 的 libicuuc.so/libicui18n.so 也打包进 APK 作为后备

5. **SELinux 拦截**
   - 现象: `avc: denied { ... }` + `tombstone` 里显示 SIGSEGV
   - 这类通常是系统权限, APK 侧无解

---

## 设备信息也很重要

脚本会自动打印, 但我特别需要知道:
- **Android 版本** (如果是 14 或更高, 32 位应用支持已被移除, 这是硬限制)
- **CPU ABI** (是否是 armeabi-v7a 或 armeabi; 如果是 arm64-v8a only 的设备, 32 位库跑不了)
- **是否 root**

```bat
adb shell getprop ro.build.version.release
adb shell getprop ro.build.version.sdk
adb shell getprop ro.product.cpu.abilist
```
