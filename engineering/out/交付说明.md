## 三、原始包为什么在新手机上跑不起来

三个独立原因，缺一不可修：

**1. ARM 转译层整数除零（SIGFPE）**
原包 `lib/armeabi-v7a/` 下只有两个 40~84 KB 的壳/加载器：`libunity.so`(43,788 B，SONAME 实为 `libunity_proxy.so`)、`libmono.so`(84,748 B)。真实库藏在 `assets/libs/armeabi-v7a/`（`libunity.so` 6,847,860 B、`libmono.so` 3,815,628 B），启动时由壳解包再 `dlopen`。
在 x86 + libhoudini 的模拟器上，这条解包路径的整数除法遇到除数为 0，ARM 语义应返回 0，houdini 却直接触发 SIGFPE 打死进程 —— 这就是「点掉权限页后进程立刻消失、crash buffer 却干净」的根因（tombstone 里 PC 全落在 `/system/lib/libhoudini.so` 的 r-xp 段）。

**2. targetSdk 15 → 每次启动弹「权限复核」页**
Android 6+ 对 targetSdk < 23 的应用强制弹 `ReviewPermissionsActivity`。

**3. targetSdk ≥ 23 时 Android 拒绝加载带 TEXTREL 的 .so**
真实 `libunity.so` 的 PT_DYNAMIC 里有 `DT_TEXTREL`，`.rel.dyn` 中确有 1 条重定位（`r_offset=0x4adfc`, `R_ARM_RELATIVE`）落在可执行段。一旦把 targetSdk 提到 23 以上，立刻 `dlopen failed: failed to link libunity.so`。

## 四、改造的做法

### ① 适配新系统

| 问题 | 做法 |
|---|---|
| 壳加载器崩溃 | 用 `assets/libs/` 里的真实 `libunity.so` / `libmono.so` **直接替换** `lib/armeabi-v7a/` 里的两个壳，绕过整个解包路径 |
| TEXTREL（真机杀手） | **改指令而不是改段权限**：把 `0x4adfc` 那个「存 GOT 槽地址、由加载器重定位」的数据字，换成 4 条 PC 相对的 ARM 指令，语义完全等价、零重定位；再把那条 `.rel.dyn` 记录清零、`DT_TEXTREL` 改成 `DT_NULL`。段权限保持原样的 **R-X** |
| 权限复核页 | `apktool.yml` 的 `targetSdkVersion` 提到 33 / 35 / 36 |
| 壳 SDK 依赖 | manifest 删除 29 个广告 / 渠道壳组件 + 4 个 kyx meta-data，`application` 去掉 `ShellApplication`，入口从 `KyxShellActivity` 改为 `com.unity3d.player.UnityPlayerActivity` |

**TEXTREL 到底怎么修的（v2 核心，两个版本共用）**

`libunity.so` 里唯一一条落在可执行段的重定位在 `.text` 最开头的一个 GOT 间接跳转 thunk（`.text` 从 `0x4adf0` 开始）：

```
原始：0x4adf0  e28f0004   add r0, pc, #4
      0x4adf4  e5900000   ldr r0, [r0]
      0x4adf8  eafffbe7   b   0x49d9c
      0x4adfc  0068f7f0   <数据：GOT 槽地址 0x68f7f0>   ← 加载器要把它重定位成 load_bias+0x68f7f0
```

改写成（不需要任何重定位）：

```
改后：0x4adf0  e30419f0   movw r1, #0x49f0
      0x4adf4  e3401024   movt r1, #0x24
      0x4adf8  e08f0001   add  r0, pc, r1
      0x4adfc  eafffbe6   b    0x49d9c
```

`add` 执行时 pc = `0x4ae00`，`0x4ae00 + 0x002449F0 = 0x68F7F0`，和原来的立即数一模一样。已用 `llvm-objdump -d` 反汇编逐条核对；也已全库扫描确认 `0x68f7f0` 只被这一处引用。

同时：把 `.rel.dyn` 里那条记录整条清零（`r_offset=0, r_info=0` → `R_ARM_NONE`），`DT_TEXTREL` 那 8 字节改成 `DT_NULL`。

**静态合规校验**（脚本 `<WORKSPACE>\bionic_check.py`）：

```
lu_notextrel.so  [('W+X-loads', 0), ('DT_TEXTREL', False), ('loads-align-not-16k', 0), ('relocs-into-exec', 0)]
libmono.so       [('W+X-loads', 0), ('DT_TEXTREL', False), ('loads-align-not-16k', 0), ('relocs-into-exec', 0)]
lu_rwx.so        [('W+X-loads', 1), ('DT_TEXTREL', False), ('loads-align-not-16k', 0), ('relocs-into-exec', 1)]   ← v1 的包，已废弃
```

段表（`llvm-readelf -l`）：`LOAD 0x000000 0x00000000 0x666720 0x666720 R E 0x8000` + `LOAD 0x666720 0x0066e720 0x210c8 0x48698 RW 0x8000` —— 与原版一致，没有 RWX。

### ③ 去内购（两个版本共用）

## 七、踩坑记录

1. **apktool 在非 ASCII 路径下回编译必失败**：`failed to open directory: 系统找不到指定的文件` + `could not exec (exit code = 1)`。所有工程一律放 `<WORKSPACE>\`。
2. **只改 `DT_TEXTREL` 标签没用**：删表项、就地改成 `DT_BIND_NOW`、改成 `DT_NULL` 三种都试过，全部仍 SIGSEGV。真正的根因是 houdini 要写受保护页，得把那条重定位本身消掉。
3. **RWX 能骗过模拟器、骗不过真机**：bionic 从 Android 10 起拒绝 W+E 段，真机上直接 `dlopen` 失败 → `No implementation found for void com.unity3d.player.UnityPlayer.nativeFile(java.lang.String)`。正解是把重定位本身消掉，段权限一点都别动。
4. **不要只换 .so 不换入口**：Kyx 壳入口会黑屏挂起在 epoll，必须走 `UnityPlayerActivity`。
5. **`extractNativeLibs` 不是 `failed to link` 的原因**：已确认 .so 确实解压到 `/data/app/*/lib/arm/` 仍在链接期失败。
6. **IL 注入点要避开被短路的分支**：`Start()` 尾部看似安全，实则被恒 false 的条件分支跳过；必须先确认 `ilspycmd -il` 里注入段在正常路径上。
7. **Cecil 里分支目标要"先建再填"**：`var skip = Mk(); EB(OpCodes.Bge, skip); ...; seq.Add(skip);`。反过来写会让 `bge` 跳到相邻下一条指令（空跳）。
8. **PowerShell 传逗号列表要加引号**：`-Sdks '33,35'`，否则被解析成数组。
9. **换版本前要清数据**：存档不区分版本，Unlocked 玩过的存档会被 Clean 照读。

## 八、可选增强（未做，如需可继续）

- **游戏内狗牌 HUD 显示 4 位**：需要改 HUD prefab 的 `SpriteText` 数量（资源侧，不是代码侧）。当前 Unlocked 版逻辑值是 9999，但游戏内 HUD 那格仍显示 99（`CommandPointsBarInGameButtons.cs:64-66/209-211` 的 clamp，该 HUD 的 `SpriteText[]` 只有 2 位，硬提会负数索引崩服）；菜单顶栏已正确显示 9999。
